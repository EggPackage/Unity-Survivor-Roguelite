## 0. 先给结论（别急着写代码）

**M1 的 4 条验收，3 条半已经有现成代码了。** 你要做的不是从零搭，是**改造 + 补一个缺口**：

| M1 验收 | 现状 | 要做什么 |
|---|---|---|
| 能移动 | ✅ `DungeonPlayerController` 已实现（Rigidbody2D.MovePosition） | **只换输入源**：旧 `InputMgr` → 新 Input System |
| 自动攻击 | ❌ **唯一真正的缺口**——现在是按 J 键手动挥砍 | **新增**：定时自动攻击 + 策略模式 + SO 配置 |
| 击杀敌人 | ✅ `Enemy.OnDeath` → `E_Monster_Dead` → `DungeonBattleManager` 计数 | 不用改，验收一遍 |
| 死亡重开 | ✅ `Health.OnDeath` → 失败面板 → `RestartBattle()`（timeScale 复位 + SceneMgr 重载） | 补一个键盘/按钮入口即可 |

**所以 M1 的真实工作量 ≈ 输入层改造 1 个 + 自动攻击 1 个 + 规范收口 3 个。** 别重开一个项目，也别复制一份代码——现有 `Game/Dungeon` 就是你的 M1 底座。

### 有坑、必须处理

1. **没有无敌帧**：`Health.TakeDamage` 每次调用都扣血。多个敌人同时贴身 → 每个敌人各自按自己的 `attackInterval` 冷却 → 伤害叠加，玩家可能 1 秒内暴毙。（M1 需求里明确写了"无敌帧"）
2. **输入层是旧版 `Input.GetAxis` + 每帧 `EventTrigger(E_Input_Horizontal/Vertical)`**：每帧广播两个 float 事件（字典查表 + 装箱风险），且改键实现是遍历整个 `KeyCode` 枚举——这是你要换掉的核心原因。
3. **`Enemy.AcquirePlayer()` 用 `GameObject.FindGameObjectWithTag`**，武器若要选目标会想用 `FindObjectsOfType`——两者都是每帧/每次调用的全场景扫描，M4 千怪场景下是明确的开销点。
4. **`PlayerAttack` 用 `Physics2D.OverlapCircleAll`**：每次调用分配一个新数组，攻击频率上去后是 GC 来源，与 M4「千怪同屏」目标直接冲突。
5. **`E_EventType.E_Player_Dead` 只有订阅方没有发布方**（`DungeonBattleManager` 注释里已记录并绕过）。新增事件时必须保证"有订阅就有发布"。

## 2. 输入层改造（你点名要新 Input System）

### 2.1 选型结论

**用 `InputActionAsset`（.inputactions）+ 生成的 C# 类，不用 `PlayerInput` 组件的 SendMessages。**

| 方案 | 判断 |
|---|---|
| 生成 C# 类，自己包装一层 | 🟢 **采用**。强类型、可断点、可单测、无反射字符串 |
| `PlayerInput` + Send Messages | 🔴 不用。靠字符串找方法，改名即失效，性能也差 |
| `PlayerInput` + Invoke C# Events | 🟡 若你想把 "PlayerInput" 写进简历，用这个（见 2.4） |

### 2.2 文件与映射

新建：`Assets/Scripts/Game/Dungeon/Input/DungeonInput.cs`（纯 C# 类或一个 MonoBehaviour 壳）
新建：`Assets/Settings/InputActions/DungeonInputActions.inputactions`（勾选 Generate C# Class，类名 `DungeonInputActions`）

| Action | Type | 绑定 | 用途 |
|---|---|---|---|
| `Move` | Value / Vector2 | WASD + 手柄左摇杆 + 触屏摇杆（M5 再绑） | 移动 |
| `Pause` | Button | ESC / 手柄 Start | 暂停（M2 用，M1 先留位） |
| `Restart` | Button | R | 死亡后重开 |

> **自动攻击不配输入键**——这是"自动攻击"的定义。M1 不要给攻击留键位，避免后面养成手动攻击的路径依赖。

### 2.3 迁移姿势（关键：**别删 `InputMgr`**）

`InputMgr` / `InputInfo` 是唐老狮 Lesson 40–43 的产物，`Bar` 模块和其他 Lesson 脚本还在用。**保留它**，只改 `DungeonPlayerController` 的 `OnEnable/OnDisable`：

- 删掉：`StartOrCloseInputMgr` / `ChangeKeyboardInfo(E_Input_Skill1, KeyCode.J)` / 三个 `E_Input_*` 事件监听
- 换成：订阅 `DungeonInput.Instance.OnMove`

**分层规范：输入层只产"意图"，不碰业务逻辑。**

```csharp
// DungeonInput 对外只暴露意图
public event Action<Vector2> OnMove;      // 每帧（或变化时）给方向
public event Action OnPause;
public event Action OnRestart;
```

业务层（Controller / BattleManager）订阅意图，永远不认识 `InputAction` / `KeyCode`。这样 M2 加手柄、M3 加改键、M5 加触屏，**业务代码一行不动**——这就是你要的"省得后面改"。

### 2.4 关于豆包建议但还没学的两块

| 章节 | 内容 | 判定 |
|---|---|---|
| **课时 19–22 PlayerInput** | 封装层，简历可写 | 🟡 **学，但 M1 不用它的默认用法**。若简历要写，用 `PlayerInput` + **Invoke C# Events**，把事件转发到我们自己的 `DungeonInput`，内部仍是强类型。**SendMessages 一律不用。** |
| **课时 28–29 改键** | 可重映射，面试加分 | 🟢 **学，排到 M1 之后、M2 之前**。改键要 UI 面板 + 持久化（`InputActionRebindingExtensions` + `SaveBindingOverridesAsJson`），成本约 1–2h，M1 塞进去会挤掉自动攻击。 |

## 3. 自动攻击（M1 唯一的核心新增）

### 3.1 结构（策略模式 + SO 配置，一步到位，M3 扩武器不改结构）

```
Config/WeaponConfig.cs      : ScriptableObject —— interval / triggerDistance / range / radius / damageMul / vfx名
Weapon/IWeaponStrategy.cs   : interface { bool CanFire(owner, cfg); void Fire(owner, cfg); }
Weapon/MeleeSwing.cs         : M1 唯一实现（复用 PlayerAttack 的判定逻辑）
Weapon/WeaponRunner.cs       : MonoBehaviour，按 interval 定时，先 CanFire 过滤再 Fire
```

`PlayerAttack.cs` 的判定逻辑**搬进 `MeleeSwing`**，原文件保留但改为被 `WeaponRunner` 驱动，或直接废弃（不删，留着对照）。

> **实施补充（自动攻击 ≠ 无条件攻击）**：初版只按 interval 开火，结果是敌人还在屏幕另一端时角色就在空挥剑。
> 因此把"够不够得着"拆成策略的 `CanFire`：近战按 `triggerDistance`（默认 = `range + radius`，即这一刀能碰到的最远处）
> 判断最近敌人是否已进范围；够不着就不挥、不播攻击动作，计时停在满值，敌人一进范围下一帧立刻出手。
> 远程/环绕武器的"可及范围"定义不同，所以这个判断必须放在策略里，不能写死在 `WeaponRunner`。

### 3.2 三条硬要求

1. **定时**：`WeaponRunner.Update` 里累加 `Time.deltaTime`，到 `interval` 触发一次。攻击间隔走 `WeaponConfig`，不在代码里写死。
2. **不空挥**：到点后先问 `_strategy.CanFire(...)`，够不着目标就跳过（不播动作、不消耗这一刀）。无目标期间计时封顶在 `interval`，不累积"连击赊账"。
3. **不分配**：`Physics2D.OverlapCircleNonAlloc` + 类级复用缓冲 `private readonly Collider2D[] _hits = new Collider2D[32];`
4. **目标从注册表取**：见 T3，不许 `FindObjectsOfType`。

## 4. 规范清单（这份文档的真正价值：防止 M2–M4 返工）

| # | 规范 | 理由 | 违反的后果 |
|---|---|---|---|
| ① | **不另起模块根目录**，M1 继续在 `Game/Dungeon` 下改；命名空间沿用 `Game.Dungeon.*` | Health/Damage/PoolMgr/GameFeel 都是通用的，复制一份就是双份维护 | M2 时两份代码行为不一致，改一处漏一处 |
| ② | **数值一律 SO 配置**，照 `EnemyConfig` 模板（新增 `WeaponConfig`、`PlayerConfig`）；Inspector 默认值兜底可以，代码里硬编码不行 | 已有先例，且是"数据驱动"这条简历卖点的证据 | M3 做 4 种武器时数值散落各处，调参靠翻代码 |
| ③ | **所有敌人/投掷物/特效走 `PoolMgr`**，且**回池必须复位状态**（照抄 `Enemy.OnEnable` 与 `Health.OnEnable` 的复位写法） | 池复用不复位 = 最经典的 bug 源（残留速度、颜色、协程） | 复用对象行为随机异常，难复现 |
| ④ | **只认 `Health` 组件**，攻击方不关心对面是玩家还是怪 | 已有设计，陷阱/AOE 才能统一走 `TakeDamage` | 每加一种伤害来源就加一套判断 |
| ⑤ | **位移统一 `FixedUpdate` + `Rigidbody2D.MovePosition`**；禁止直接改 `transform.position`（旧 `PlayerController2D.cs` 是反例，别抄） | 与碰撞/物理同步，不会穿墙抖动 | 高速移动穿墙、与碰撞体打架 |
| ⑥ | **时间**：顿帧/结算用 `timeScale`；所有等待与 UI 用 `Time.unscaledDeltaTime`（`Enemy.FlashRoutine` 已是正确示范）；**重开/进场景必先 `Time.timeScale = 1f`** | `DungeonBootstrap` 已在兜底 | 顿帧后场景冻结、看起来"卡死" |
| ⑦ | **GC 三禁**：禁每帧 `Find*`/`FindObjectsOfType`、禁 `OverlapCircleAll`（改 `NonAlloc`）、禁每帧字符串拼接（HUD 只在数值变化时刷新） | M4 目标是千怪同屏，GC Alloc 要平稳 | M4 时被迫回头重构战斗层 |
| ⑧ | **资源加载一律走 `ResMgr` / `ABResMgr` 接口**，业务代码不直接 `Resources.Load` | M1 用 Resources，M4 换 Addressables 时**只改底层，业务零改动** | 现在图省事直连 Resources，M4 全项目改一遍 |
| ⑨ | **单例用法**：跨场景全局用 `BaseManager`（纯 C#）；场景内引用面板/刷怪器的一律挂 MonoBehaviour，**单例绝不持有场景对象引用** | `DungeonBattleManager` 头部注释已论证 | 切场景后悬空引用、MissingReference |
| ⑩ | **事件**：新增事件必须加进 `E_EventType.cs`，且**有订阅必须有发布**（`E_Player_Dead` 是反面教材） | 事件中心是字典查表，拼错/漏发布都是静默失效 | 调试半天发现是没人发这个事件 |
| ⑪ | **死亡只触发一次**：`OnDeath` 回调里用 bool 守卫（`Enemy._isDying` 已做） | `Health` 不保证只调一次 | 重复结算、重复回池 |
| ⑫ | **输入层只产意图**（见 2.3），业务层不认识 `KeyCode`/`InputAction` | 为 M2 手柄 / M5 触屏 / 改键留口子 | 每次加输入方式都改业务代码 |

### 6.1 实施偏差记录（与 2.1 的偏差，已确认）

- **T1 输入层用"内联构建 `InputActionMap`"，未采用 `.inputactions` + 生成 C# 类。**
  理由：零外部资产依赖、首编译即可用、纯 C# 可断点、不踩生成类时序。代价：改键不能可视化。
  M3 做可视化改键时，可改为 `Resources.Load<InputActionAsset>` 加载 `.inputactions` 并转发到 `DungeonInput`，**对外事件契约不变**。
- **T1 保留 `DungeonInput.OnAttack`（J / 鼠标左键）作为 TEMP 桥接**，T2 自动攻击落地后删除该事件与订阅。
