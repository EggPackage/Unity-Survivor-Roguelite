## 7. 修复（2026-10-28 傍晚）：近战对着远处敌人空挥

**现象**：敌人在屏幕另一端时，角色照样每 0.8 秒挥一次剑，等敌人真正靠近才打得到。

**根因**：`WeaponRunner.Update` 是纯定时器——`_timer` 到 `interval` 就 `Fire()` + `OnFired`，中间没有任何"目标在哪"的判断。`MeleeSwing.Fire` 里虽然有判定圆，但那是在**开火之后**才画的，打不到只是"这一刀空挥"，不影响它挥。**"够不够得着"这件事从来没被问过。**

| 文件 | 行 | 改动 |
|---|---|---|
| `Combat/ActorRegistry.cs` | 51–70 | 新增 `GetNearestEnemySqrDistance(Vector2)`：最近存活敌人的距离**平方**（无敌人返回 `float.MaxValue`）。返回平方值是为了判定时省一次开方——比较 `sqr <= reach * reach` 即可 |
| `Weapon/IWeaponStrategy.cs` | 15–24 | 新增 `bool CanFire(Transform, WeaponConfig)` |
| `Weapon/MeleeSwing.cs` | 33–41 | 实现 `CanFire`：`reach = triggerDistance > 0 ? triggerDistance : range + radius`，最近敌人超出 `reach` 就返回 false |
| `Config/WeaponConfig.cs` | 27–29 | 新增 `triggerDistance`（默认 0 = 自动取 `range + radius`） |
| `Weapon/WeaponRunner.cs` | 88–97 | 到点后先 `if (!_strategy.CanFire(...)) return;`，通过才 `Fire` + `OnFired` |
| `Weapon/WeaponRunner.cs` | 90 | `_timer` 封顶在 `interval`：没目标期间不累积"连击赊账" |

**四个决定，以及为什么不是别的写法：**

1. **`CanFire` 放策略里，不写死在 `WeaponRunner`。** 近战的"够得着"是"目标进了挥砍圆"，远程的可能是"场上有敌人就射"，环绕的是"半径内有人"。写死在 Runner 里，M3 加第二种武器就得回头改 Runner —— 正好违反加策略模式的目的。
2. **`reach` 用 `range + radius` 自动算。** 判定圆心沿攻击方向偏移 `range`、圆半径 `radius`，所以这一刀最远够到 `range + radius`。让公式跟着判定形状走，改判定参数时索敌距离自动跟上，不用同步调两个数。需要单独调（长柄、大范围）时再填 `triggerDistance`。
3. **计时封顶而不是清零。** 清零会让"敌人进范围"到"第一刀"之间白等最多一个 `interval`（0.8s），手感发木；封顶则保留满计时，**进范围下一帧立刻出手**。若完全不封顶，`_timer` 会一直涨，敌人一来就连打十几刀——所以必须封顶。
4. **用平方距离，不开方。** 判定只需要比大小，`Mathf.Sqrt` 每次都算一遍纯属浪费。这条属于规范⑦ 的延伸（省的不只是 GC，还有无意义的算力）。

**仍然是零分配**：新增的判断只遍历 `ActorRegistry` 的静态 `List<Health>`，没有数组分配，也没有 `Find*`。开火路径的 GC 分配依然为 0。
